# 禁漫天堂插件（Breeze）

Breeze 的「禁漫天堂」漫画源插件。宿主 App：[`deretame/Breeze`](https://github.com/deretame/Breeze)。

## 功能

- 首页推荐 / 最新 / 排行榜 / 云端收藏
- 搜索、详情、阅读、评论、收藏
- **标签组合搜索**：多个标签取交集，结果里的本子**同时**带齐所有标签
- **基于标签的相关推荐**：详情页底部「相关推荐」按本子标签算相似度，不再是服务端那份"同题材老本子"

## 标签组合搜索

### 用法

- 搜索框直接写加号：`后宫+校园`（也支持全角 `＋`）
- 或在搜索页点右上角「调节（调音图标）」→ 在「主题A漫 / 角色扮演 / 特殊PLAY / 其他 / 常用标签」里跨分组勾选 → 应用
- 关键词 + 勾选标签可以组合，等价于「关键词 AND 这些标签」

### 为什么需要客户端实现

禁漫移动端 API 的 `/search` **没有**多标签过滤参数。2026-10 实测：

| 参数 | 效果 |
| --- | --- |
| `search_query` | 有效，但多个词之间是 **OR**（`后宫 校园` = 7069 条，是两者并集） |
| `c` | 有效，单个分类 slug（`c=doujin` / `c=single`） |
| `main_tag` | 有效，0=站内 1=作品 2=作者 3=标签 |
| `c[]` / `tags[]` / `tag[]` / `t=` | **全部无效**（传了跟没传一样） |

所以「同时命中多个标签」只能在客户端做：每个条件各拉一份结果集 → **求交集** → 交集里的本子必然同时命中所有条件。

纯标签组合时交集本身就是精确结果（实测 `后宫+校园` 20/20、`剧情向+校园` 10/10、`非H+校园` 39/39 全部同时带齐），
**不再逐本拉 `/album` 核对**（那一步最贵）；混有普通关键词时才核对，保证关键词也真的命中。

### 性能

禁漫每请求约 450~500ms，所以关键是少发请求：

| 场景 | 请求数 | 耗时 | 一页结果 |
| --- | --- | --- | --- |
| 普通搜索 / 单个标签 | 1 | ~1s | 80 |
| 两个标签 | 32（并发 24） | ~1.5~2.5s | 10~40 |
| 三个标签 | 32（并发 24，按条件数摊薄） | ~1.5~2.5s | 视组合而定 |
| 翻页 | 再 +16 | ~1s | 逐步变多 |

- 单个条件直接走普通搜索（1 个请求），速度与普通搜索一致
- 同一页的多个请求**一轮并发**拉完（分多轮拉会把每轮延迟叠加）
- 某一页请求失败只少那一页，不会让整次搜索报错
- 条件词的结果集进程内缓存，换组合可复用

### 已知限制

- **结果数取决于组合本身**：禁漫不同标签的结果集密度差很多（`巨乳` 一天 80 本，`校园` 一个月才 80 本），
  所以「热门标签 + 冷门标签」在最近窗口内本来就只有几条，往下翻会逐步变多
- 官方 `/categories` 只给 47 个「主题标签」，实际本子标签有近 900 个，插件另外内置了 86 个高频的
- `自慰` 在本子里实际写的是 `手淫`，已做别名映射
- 禁漫的 `/categories` 节点有时回繁体有时回简体，插件内部统一转简体后再比对

## 基于标签的相关推荐

详情页底部「相关推荐」原本是禁漫服务端 `related_list` 原样透传，实测那东西是
**「同题材里 id 最小（最老）的那批」**——每个本子固定 12 条，只带 `id/author/name/image`
（没有标签），而且严格按 id 升序，所以推出来的往往是几年前的老本子。

现在改成自己算：

1. 取本子自己的标签，滤掉 `中文`/`连载中`/`完结`/`单行本`/`禁漫书库` 这类没有区分度的元信息标签，最多用 5 个
2. 每个标签并发跑一次标签检索（`main_tag=3`），一批就够
3. 统计每个候选命中了几个标签 → **命中越多越像**；同样命中数时，**标签越冷门越有区分度**
4. 排除本子自己，取前 12 条

实测（用原始接口逐条独立复核）：

| 本子标签 | 抽检推荐共享标签数 |
| --- | --- |
| 青年漫 / 校园 / 爱情 / 中文 | 6 条全部共享 **4** 个 |
| 韩漫 / 后宫 / 人妻 / 诱惑 / 中文 | 6 条共享 **3~4** 个 |
| 堕落 / 怪物女孩 / 催眠 / 群交 / 3D / 中文 | 6 条共享 **3~5** 个 |

（服务端原 related_list 只能共享 1 个标签。）

本子没有可用标签、或标签检索全失败时，会自动退回服务端那份 `related_list`。
标签检索单独设 6 秒超时，不让详情页陪着一起等。

## 开发

```bash
# 依赖
pnpm install

# 类型检查 + 打包(含 manifest / version 同步 / brotli)
pnpm build

# 离线单测(25 项, 不联网)
node --import tsx test/tag-search.test.ts
```

改动集中在：

- `src/tag-search.ts`（新增）：条件词拆分、标签体系解析、交集运算、标签匹配、别名表
- `src/index.ts`：`searchComic` 多条件 AND 分支、`getAdvancedSearchScheme` 标签多选字段
- `test/tag-search.test.ts`（新增）：纯逻辑单测
